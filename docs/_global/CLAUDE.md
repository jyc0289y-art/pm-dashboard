3. **이유**: 타 프로젝트의 실제 세션이 병행 중일 수 있어, 대행 실행 시 **이중 작업·git 충돌·기록물(registry/CLAUDE.md) 경합**이 발생한다(P40 3과 사례: 두 세션이 같은 작업을 각자 실행할 뻔함).
4. Claude 자신도 마찬가지: 산출물을 쓰기 전에 대상 경로가 현재 프로젝트 소속인지 확인하고, 타 프로젝트 파일을 수정해야 할 정당한 사유가 있으면 먼저 사용자에게 알린다.

## 사용자 검수 요청 사전 검증 의무 (Pre-QA Self-Validation)

> **추가 일자**: 2026-05-06 (사용자 지시: "내 노동력을 줄이기 위해 시스템 만들고 있는데 의미없는 검수 요청은 노동력 낭비. 검수가 의미있는지 사전 검토")

**사용자에게 검수 요청 알림을 보내기 전에 다음 5개 게이트 모두 자동 통과해야 한다. 하나라도 실패 시 재처리 → 재검증 → 통과 후 알림 발송.**

### 게이트 G1 — 산출물 최신성
- 산출물 timestamp가 모든 입력 자산의 마지막 수정 시점 **이후**여야 함
- 검사: `산출물.mtime > max(입력자산들.mtime)`
- 위반 시: "재빌드 안 됨" 자동 감지 → 빌드 트리거

### 게이트 G2 — 자동 결함 검출 통과
영상/이미지에 다음을 자동 검사:
- **OCR 결함 텍스트**: 영상 프레임 샘플 5~10개 OCR → 한글/일본/중국 텍스트 발견 시 fail (의도된 자막 제외)
- **moov atom 위치**: 파일 시작 부분 (faststart 적용됨)
- **코덱 호환성**: H.264 baseline/main + AAC + yuv420p
- **빈 프레임**: 검정/단색 프레임이 0.5초 이상 연속되면 검토 트리거
- **자막 동기화**: 자막 timing이 audio 발화와 ±200ms 이내

### 게이트 G3 — 이전 사용자 지적 반영 확인

### 게이트 G4 — 변화 발생
- 이전 빌드 대비 정량 지표 또는 시각 변화 측정 (`qa_build_compare.py` 결과)

### 게이트 G5 — AI 한계 명시

## 사용자 검수 요청 의무 (User Verification Interface Rule)

> **추가 일자**: 2026-04-17 (사용자 지시: "프로젝트 중단 원인은 직접 검증 요청 단계 — HTML로 게시하고 클릭 피드백")

**시각/청각 산출물(영상·이미지·HTML·문서)을 사용자에게 검수 요청할 때 텍스트 묘사로만 끝내지 않는다. 반드시 사용자가 클릭/선택으로 피드백을 줄 수 있는 인터페이스를 제공한다.**

### 규칙 1: 검수 페이지 자동 생성 의무
검수 대상이 **영상·이미지·다층 시각물**인 경우, 다음을 포함한 단일 HTML 페이지를 생성한다:
- **헤더에 `P{N} · {프로젝트명}` 식별 표기 필수**(2026-06-11 P38: 여러 프로젝트 동시 보고 시 구분 — 제목 또는 부제 맨 앞에)
- 산출물 직접 재생/표시 (HTML5 video, img tag)
- **같은 시점 / 같은 좌표 비교** (PREV vs NEW 그리드)
- **시점별/항목별 체크리스트** (good/needs-fix/critical 라디오 + 자유 코멘트)
- **피드백 복사 버튼** → 구조화 텍스트(JSON/Markdown)를 클립보드로 → 사용자가 채팅창에 붙여넣기 가능

### 규칙 2: 표준 위치
- HTML 산출물: `{프로젝트}/docs/qa_review/qa_{YYYYMMDD_HHMMSS}_{설명}.html`
- 의존 자산(프레임 이미지·복사 영상): 같은 디렉토리 또는 `{ts}_assets/` 하위
- **단일 폴더로 자가완결** (브라우저로 열면 외부 의존 없이 동작)
- **★프로젝트 식별 배지 필수 (2026-06-11, P40에서 격상)**: 모든 검수 페이지·HTML 보고서 머리에 **`P{N} · {프로젝트명}` 배지**를 눈에 띄게 표시 + `<title>`에 `[P{N}]` 접두. 여러 프로젝트가 동시에 보고하면 사용자가 구분 불가(P38·P40 혼동 사례).

### 규칙 3: 글로벌 스크립트
- `~/.claude/scripts/generate_qa_page.py` 사용 (없으면 P21 FEP `EP01_forced_compliment/qa_review_page.py` 참조)
- 입력: NEW/PREV 영상 경로 + 비교 시점 리스트 + 체크리스트 항목
- 출력: 단일 HTML 페이지 + 자동 브라우저 오픈 (`open` 명령)

### 규칙 4: 사용자 피드백 형식
HTML 페이지의 "피드백 복사" 버튼은 다음 형식의 텍스트를 클립보드에 넣는다:
```markdown
## QA 피드백 — {빌드명}
- 115s 03_validation: ✅ 정상 / 🟡 위치 어색 / 🔴 자막 가림
- 280s 다층 자막: 🟡 Type D와 Type F 겹침
- 자유 코멘트: ...
```
사용자가 이를 채팅창에 붙여넣으면 AI가 즉시 항목별 수정 진행.

### 규칙 5: 텍스트만의 검수 요청 금지
- ❌ "확인해주세요", "괜찮은지 봐주세요" 만 보내고 작업 종료
- ✅ HTML 페이지 경로 + `open` 명령 + 체크리스트 항목 미리보기 함께 제공

### 규칙 6: 철저한 캡쳐 — 시간 제약 사용자를 위한 피드백 준비 (P36에서 격상, 2026-06-06)
> 사용자 지시: "캡쳐가 꼼꼼히 들어갔다면 피드백으로 회신된 내용이 훨씬 많았을 것. 사람은 시간이 항상 제약돼서, 미리 준비해줄 수 있는 부분을 챙겨주지 않으면 의지가 있어도 피드백을 줄 수 없다."

**핵심 원칙: 피드백의 병목은 사용자의 의지가 아니라 시간이다. 피드백 비용을 최소화하도록 미리 다 준비한다.**

1. **기능·상태별로 충분히 캡쳐**: 각 신규 기능을 *대표 화면 1장*으로 끝내지 말 것. 핵심 상태(예: 신생/성장/고레벨, 정상/위기, before/after, 빈/채워진)별로 스크린샷을 담아 사용자가 *그 자리에서* 보고 판단할 수 있게 한다. 자율 빌드(사용자 부재) 중일수록 더 꼼꼼히.
2. **검수 페이지에 스크린샷 인라인 임베드**: 직접 앱/기기를 켜지 않아도 페이지만 보면 변경을 한눈에 — 텍스트 설명 + 캡쳐 이미지를 항목마다 함께. (네이티브 앱은 시뮬레이터 캡쳐를 `{ts}_assets/`에 저장 후 `<img>`로 임베드.)
   - **★배치 원칙 (2026-07-12 P40 TRAP-008→P48 TRAP-006 재발로 전역 격상)**: 캡쳐를 상단 갤러리에 몰아넣고 문항과 분리 금지. **각 검수 문항 바로 아래에 그 문항 전용 크롭(핵심 영역만) + '볼 곳' 1줄 + 전→후 델타를 동거 배치**, 크롭 클릭=원본 전체 오버레이. "문항↔캡처 매칭을 사용자가 하게 만들면 검수 부하 절감 실패"(오너 원문). 게시 전 크롭 전수 Read 자가 검사 의무(오크롭 적발). ⚠️sips 크롭 offset 0 0 금지(중앙 크롭 오동작 — 최소 2 2).
3. **체크리스트는 항목별 ✅/🟡/🔴 + 코멘트 + 복사 버튼**(규칙 1·4). 사용자가 *해본 것만* 체크하고 부분 회신 가능하게.
   - **★코멘트 입력란 = 여러 줄 `<textarea>` (2026-07-15 P49 오너 지시로 격상)**: 한 줄 `<input>` 금지 — 오너 원문 *"코멘트 입력란 줄바꿈해서 코멘트 전체를 보고 편집하기 편하게"*. 최소 3행·세로 리사이즈 허용(`resize:vertical`)·입력에 따라 자동 확장 권장. 긴 피드백이 검수의 핵심 산출물인데 한 줄 칸은 작성 자체를 억제한다.
   - **★결의·요약 문항에는 근거 딥링크 동반**(누적 보고서 규칙 8과 동일 취지): 검수 문항이 결의·수치를 요약해 묻는다면 "어느 회의록 어느 절"인지 링크를 문항 옆에 둔다. 오너가 세부를 못 찾으면 회신 불가.

   - **갱신 트리거**: 분과 신설·폐지·배속 변경·위원장 교체·주요 의결·매 보고 라운드 → divisions의 `current`/`recent`/`updated`를 갱신 후 재생성. 엔진이 전역 공유이므로 **모든 프로젝트에 자동 적용** — 분과 보유 프로젝트가 누적 보고서를 갱신할 때 divisions 최신화는 의무. 정본 예시: P48 `docs/report/gen_session_report.py`의 `DIVISIONS`.

10. **★「한눈에」 현황요약 + 매 턴 갱신 + 라운드 3층 구조 (2026-07-22 P50 오너 지시로 격상)**: 오너 원문 — *"현황요약 아주 훌륭해. **현황요약 매턴마다 이렇게 업데이트**해서 내 판단을 도와줬으면 좋겠어. 그리고 **사이드바의 각 턴 페이지에 접속해도 이렇게 일목요연하게** 정리되어 있었으면 좋겠어."* (계기: 같은 오너가 직전에 *"누적보고서 엉망이야. 가독성도 떨어지고 시각화도 되지 않고 용어도 정리되어있지 않아서 **너만 알아볼 수 있는 자료**에 가까워"*라고 혹평. 실측 결과 본문 37만 자·도식 0개·설명 없는 전문용어 수백 회였다.)

   **⓪ 진단 원칙**: 오너가 "너만 알아볼 자료"라고 하면 **문체가 아니라 구조 문제**다. 진입 화면이 과거형 아카이브(개요·타임라인)라 *"지금 어디까지 왔고 내가 뭘 정해야 하나"*에 답하지 못하는 것이 근본 원인이다.

   **① 「📊 한눈에」를 진입 탭으로 (필수)** — `meta["dashboard"] = {"html": ..., "svg": ...}`. 엔진이 **맨 앞 탭 + 첫 화면**으로 렌더한다. 구성 4종:
   - **헤드라인 1~3문장** — 전문용어 0개. "무엇이 완성됐고 / 지금 멈춰 있는 건 무엇이고 / 오너 결정이 몇 건인지".
   - **신호등 3칸** — ✅끝난 것 / ⏳오너를 기다리는 것 / ⛔못 하는 것(기술 한계·결정 불요). `statuscard st-done|st-wait|st-block`.
   - **결정 대기 카드** — 항목마다 ①질문 1문장 ②**안 하면 어떻게 되는지** ③선택지. 오너가 그 자리에서 답할 수 있게.
   - **최근 변경 3건** — 날짜 · 바뀐 것 · **전→후**.
   - **시스템 도식 SVG 1장**(선택) — 구성요소 관계. `viewBox` + 다크/라이트 대응.

   **② 매 턴 갱신 의무** — 라운드를 추가하는 턴마다 **대시보드도 함께 갱신**한다(기준 시각·신호등·결정 대기·최근 변경). 라운드만 쌓고 대시보드를 방치하면 규칙 위반. 오너의 판단 창구이므로 최신성이 핵심.

   **③ 라운드 3층 구조 (필수)** — 각 라운드 dict에 `tldr`(3줄 내외 리스트)·`decision`(이 턴에 정해진 것 1줄). 엔진이 **①요약 항상 노출 ②「자세히 보기」 접기 ③「증거·산출물」 접기**로 렌더한다. 라운드 첫 화면은 **뷰포트 1개 이내**. 미지정 라운드는 기존처럼 펼쳐 렌더(하위 호환).

   **④ 「📖 용어 사전」 탭** — `meta["glossary"] = [{term, plain, analogy}]`. 보고서에 나오는 용어를 **오너 언어로 치환**하고 비유를 단다. 예: `lid`→"기기 꼬리표(이름이 인쇄된 항공권)", `래칫`→"되감기 방지 시계", `리스 토큰`→"24시간짜리 입장 팔찌".

   **⑤ 서술 규칙** — ⓐ 내부 식별자를 **번호 단독으로 쓰지 말 것**(`TRAP-017` ✕ → `함정 #17 「키쌍 혼선」` ○). ⓑ 한 문장 60자 내외·능동태·명사 나열 금지. ⓒ 문단 첫 문장이 결론. ⓓ 파일 경로·함수명 등 **오너가 쓸 일 없는 내부 참조는 본문에서 빼고** 접힌 상세로.

   → 엔진 `session_report.py`가 `dashboard`·`glossary`·`tldr`·`decision`을 **전부 하위호환으로 지원**한다(미지정 프로젝트는 기존과 동일). 즉 **모든 프로젝트가 키만 채우면 즉시 적용**된다. 정본 예시: P50 `docs/report/gen_session_report.py`.

11. **★모든 라운드에 시각 증거 의무 — 글자만 있는 라운드 금지 (2026-07-27 P50 오너 지시로 격상)**: 오너 원문 — *"누적보고서에 **텍스트만 주저리주저리 적지말고 그 턴의 결과물들좀 삽입해**. 봐도 **기억도 안나** 그냥 글자만 써놓으면. 결과물이 이미지면 그걸 첨부하고, **결과물이 이미지가 아니더라도 어떤 캡쳐나 시각자료를 넣어줘야 기억이 날거 아냐**."*

    **⓪ 진단**: 보고서는 오너가 **나중에 되짚는** 물건이다. 텍스트 요약은 쓸 때는 충분해 보여도 몇 턴 뒤엔 어느 턴에 뭘 했는지 되살리지 못한다. **시각 자료는 기억의 인덱스**다 — 그림 한 장이 그 턴을 통째로 불러온다.

    **① 규칙: 라운드마다 `figs` 최소 1장** (예외 없음 — 순수 대화·질의응답 턴만 면제). 코드·수치·설계처럼 "결과물이 이미지가 아닌" 턴이 **바로 이 규칙의 대상**이다. 그럴 때 무엇을 넣는가:
    - **앱·UI 변경** → 시뮬레이터/기기 스크린샷 (전·후 쌍)
    - **수치·측정·통계** → 표를 그린 차트 PNG 또는 결과표 렌더 이미지 (matplotlib·PIL·HTML→캡처 무엇이든)
    - **코드·아키텍처** → 구조 도식 SVG, 또는 **핵심 diff를 문법강조해 렌더한 이미지**
    - **터미널 작업(빌드·배포·검증)** → 그 출력의 캡처 이미지 (텍스트 붙여넣기가 아니라 **그림으로**)
    - **문서·기록물** → 그 문서의 첫 화면 렌더 캡처
    - **분과·패널 회의** → 결의 요지를 담은 카드형 도식
    → 진짜로 만들 게 없으면 **그 턴에 무엇이 달라졌는지 보여주는 전·후 비교 그림을 만들어라**. "만들 시각자료가 없다"는 대개 **안 만든 것**이다.

    **② 캡션·상세는 규칙 7 형식 그대로**: fig 4-튜플 `(경로, 캡션, 상세md, 그룹제목)`. 캡션만으로 이해가 안 되는 그림은 상세 필수.

    **③ 소급 적용**: 기존 라운드 중 `figs`가 빈 것은 **규칙 위반 상태**다. 보고서를 갱신하는 김에 과거 라운드도 시각 자료를 채운다(당시 산출물이 남아 있으면 그것을, 없으면 지금 재현해서라도).

    **④ 자가 검사**: 보고서 생성기에 **figs 없는 라운드를 세어 경고**하는 검사를 넣는다. P50 정본: `gen_session_report.py`가 생성 직후 빈 라운드 목록을 stderr로 출력.

12. **★「✅ 작업 추적」 탭 의무 — 지시 누락을 오너가 직접 확인할 수 있게 (2026-07-27 P51 오너 지시로 격상)**: 오너 원문 — *"작업누락방지 추적에관한 사항도 누적보고서에 누적기록해서 내가 확인할 수 있도록 하고 전역지침에 반영해."*

    **⓪ 왜 필요한가**: 어시스턴트의 내부 작업 목록(TaskCreate/TaskList)은 **오너가 볼 수 없고, 컨텍스트 리셋으로 통째로 사라진다**(P51 실사례: 등록한 10건이 전부 소실됐고 어시스턴트는 그걸 알고도 재등록하지 않았다). 추적 장치가 어시스턴트 머릿속에만 있으면 누락을 오너가 뒤늦게 발견하게 된다. **보고서에 남겨야 추적이 성립한다.**

    **① 누적 보고서에 `meta["task_ledger"]`를 채운다** (전역 엔진이 「✅ 작업 추적」 탭으로 렌더):
    ```python
    task_ledger = {
      "updated": "YYYY-MM-DD HH:MM",
      "note": "상단 안내 1줄",
      "rounds": [                      # ★ 누적 — 과거 턴을 지우지 않는다
        {"turn": "r2", "date": "...",
         "given":  ["이 턴에 오너가 준 지시 (원문에 가깝게)"],
         "done":   ["이 턴에 실제로 끝낸 것"],
         "open":   ["미완 — 다음 턴 이월"],
         "missed": ["누락했다가 발견한 것"]},   # ← 정직 표기, 삭제 금지
      ]}
    ```
    엔진이 **최신 라운드의 `open`을 맨 위에 크게** 띄우므로, 오너는 탭 하나만 열면 "지금 뭐가 밀려 있나"를 즉시 본다.

    **② 매 턴 갱신 의무** — 라운드를 추가하는 턴마다 `task_ledger`에도 그 턴 스냅샷을 append한다. 대시보드(규칙 10)와 같은 취급이다. 라운드만 쌓고 원장을 방치하면 규칙 위반.

    **③ `missed`는 반드시 남긴다** — 누락을 발견해 처리했더라도 **기록을 지우지 않는다**(콘텐츠 보존 규칙·정직 표기와 동일 취지). 같은 종류의 누락이 반복되는지는 이 칸을 시간순으로 봐야만 드러난다.

    **④ 내부 작업목록과 이중화** — TaskCreate/TaskList는 계속 쓰되, **보고서 원장이 정본**이다. 컨텍스트 리셋으로 내부 목록이 비면 **보고서 원장에서 복원**한다.

### 규칙 1: 산출물 파일명에 타임스탬프 필수
**반복 빌드/생성 가능한 산출물(영상, 이미지, 보고서, 모델, 빌드 아티팩트 등)은 반드시 타임스탬프 접두사를 포함한다.**
- 형식: `YYYYMMDD_HHMMSS_{설명}.{확장자}`
- 적용 대상:
  - 영상 빌드 (`output/20260417_014924_EP01_v3_lp_bubble.mp4`)
  - 이미지/일러스트 (`v3_layers/...`)
  - 분석 보고서, 측정 결과 JSON
  - 모델 체크포인트, 데이터셋 스냅샷
  - 컴파일된 바이너리 (반복 가능한 것)
- **금지**: 같은 파일명으로 덮어쓰기 (`output.mp4`, `result.json` 등 고정명)
- **예외**: 임시 작업 파일(`/tmp/*`), 캐시(`__pycache__`), 의존성 잠금(`package-lock.json`)

### 규칙 2: 개선 작업 후 비교 평가 의무
**"개선됨" 또는 "고침"이라고 보고하기 전에 반드시 다음을 수행:**

1. **이전 산출물 보존 확인**: 이전 버전이 같은 디렉토리에 보존되어 있는지 확인. 없으면 즉시 사용자에게 보고하고 작업 중단.
2. **정량 비교 측정**: 사용 가능한 객관적 지표로 이전 vs 현재 측정값 표 작성
   - 영상: 길이, 크기, 씬 수, 자막 수, 측정 가능한 품질 지표
   - 코드: 테스트 통과율, 성능 벤치마크, LOC, 복잡도
   - 데이터: 샘플 수, 정확도, 손실값
3. **시각/청각 검증** (해당 시): 같은 위치(타임스탬프/좌표)에서 이전 vs 현재 샘플 추출
4. **회귀 항목 명시**: 개선 항목 + **퇴보/유지 항목**도 빠짐없이 보고

### 규칙 3: "개선됨" 선언 유예
- AI(Claude)는 오디오 청취 불가, 영상 재생 관찰 불가, 사용자 체감 추정 불가
- 따라서 정량 지표가 좋아져도 **"개선됨"이라 단정하지 말고 "개선 시도"로만 표기**

## 콘텐츠 무단 누락 금지 (Content Preservation Rule)

기존 결과물(보고서, 문서, 코드 등)을 수정·업데이트할 때, **사용자가 명시적으로 삭제/제거를 요청하지 않은 기존 콘텐츠는 절대 누락시키지 않는다.**

### 원칙
1. **추가는 자유, 삭제는 허가제**: 새로운 콘텐츠 추가는 자유롭게 가능하나, 기존 콘텐츠의 삭제·축약·생략은 사용자의 명시적 요청이 있을 때만 허용
2. **섹션 교체 시 전수 확인**: 기존 섹션을 새 내용으로 교체할 때, 교체 전 섹션에 포함된 모든 정보 항목이 새 섹션에도 존재하는지 확인
3. **의심스러우면 유지**: 특정 콘텐츠의 포함 여부가 불확실하면 포함하는 쪽을 선택

## 재사용 모듈 시스템 (MOD)

프로젝트 간 포크 가능한 독립 코드 모듈을 `MOD-{NNN}` 번호로 관리한다. "MOD-001 포크해줘"로 즉시 통합.
→ **레지스트리**: `~/.claude/modules/_index.md` — 포크 요청 시 Read
→ **개별 카드**: `~/.claude/modules/MOD-{NNN}_{name}.md` — 소스 경로, 포크 방법, API, 변경/포크 이력
→ **상세 규칙이 30줄 초과 시**: `~/.claude/instructions/mod_system.md`로 분리

**핵심 3줄:**
- **등록**: 독립 모듈 완성 시 `_index.md` + 상세 카드 즉시 생성
- **포크**: 상세 카드 읽기 → 소스 복사 → 통합 → 포크 이력 갱신
- **업데이트**: 원본 변경 시 카드 버전 bump + 변경 이력 추가 + `_index.md` 갱신

3. **하위 경로** (등록 프로젝트의 서브폴더이지만 그 자체는 미등록): 사용자에게 선택지 제시하고 답변 대기

   - (b) 상위 {P번호}의 임시 작업공간으로 진행

**채팅번호 할당 안전망 (타임스탬프 재확인)**: 새 채팅 개시 시 registry를 한 번 더 재read하여 max가 변했는지 확인. 변했으면 더 큰 값 사용. 동시 개시 채팅 간 경쟁 조건 최소화.

### 세션 번호 체계 (4계층, 2026-04-15 시행)

**형식**: `P{프로젝트}.{채팅}.{포크}.{Agent}` — `wc` 등 정책 태그는 폐지

| 계층 | 의미 | 증가 시점 |
|------|------|-----------|
| 프로젝트 N | 프로젝트 번호 | 신규 프로젝트 생성 (전역) |
| 채팅 C | 채팅창 식별 | 새 채팅창 개시 (registry SSOT) |
| 포크 F | 자동포크 식별 | 같은 채팅 내 압축·자동포크 (채팅 내) |
| Agent A | Agent 파견 식별 | `.0`=원본 스레드, `.1+`=Agent (포크 내) |

**증가 규칙**:
- **새 채팅 개시**: `registry.md` max 채팅번호 +1 → `P{N}.{max+1}.1.0`
- **같은 채팅 내 자동포크**(압축 등): 채팅 고정, 포크 +1, Agent=0 리셋
  - 예: `P3.28.1.0` → 압축 → `P3.28.2.0`
- **Agent 파견**: 채팅·포크 고정, Agent +1
  - 예: `P3.28.1.0` → 파견 → `P3.28.1.1`, 또 파견 → `P3.28.1.2`
- **Agent 내부에서 또 Agent 파견**: 계층 증가 금지, Agent번호만 +1 (`.1.1.1.1` 꼬리 방지)
- **타 프로젝트 Agent 파견**: 대상 프로젝트 registry에서 새 채팅번호 할당
  - 예: `PM.17.1.0`이 P3에 파견 → P3 registry max=28 → `P3.29.1.0` 생성
- **교차채팅 포크**(채팅 오류로 재개설): 새 채팅번호 할당, 족보는 **`포크원` 필드로만 추적**
  - 예: `P1.3.5.0` 오류 → 새 채팅 `P1.4.1.0` (포크원: `P1.3.5.0`)
  - **계층을 끌어올리지 않는다** (루트번호만으로 포크체인을 추적하지 않음)

**유산 세션 호환**: 2026-04-14 이전 평면 번호(`P3.28wc` 등)는 그대로 보존. 해당 세션에서 신규 포크 발생 시부터 4계층 적용 (유산 번호는 묵시적 `.1.0`으로 간주: `P3.28wc` → 압축 → `P3.28.2.0`).

### 규칙 (필수)

1. **새 지시 수신 즉시 등록** — 사용자 메시지에 **작업이 2건 이상**이거나, 턴 중간에 새 지시가
   삽입되면 **먼저 `TaskCreate`로 전부 등록**한 뒤 실행에 들어간다. 등록을 미루고 "기억해서
   하겠다"는 금지. 즉시 처리되는 1건짜리 사소한 요청은 예외.
2. **착수·완료 표시** — 작업 시작 시 `in_progress`, 실제로 끝났을 때만 `completed`.
   부분 완료·검증 실패는 완료로 표시하지 않는다.
3. **턴 종료 전 자가 점검 (의무)** — 응답을 마치기 전 `TaskList`로 미완 작업을 확인하고,
   **남은 것이 있으면 응답에 명시**한다("남은 작업: N건 — …"). 사용자가 묻지 않아도 한다.
4. **"누락 확인" 요청 시 전수 점검** — 사용자가 누락을 물으면 TaskList + 대화 전문을 대조해

5. **장시간 대기 중 재확인** — 백그라운드 작업(빌드·생성·워크플로)을 기다리는 동안
   **다른 미완 작업을 먼저 처리**한다. 대기가 곧 유휴가 되어선 안 된다.
6. **완료 보고의 정직성** — "했다"고 보고하기 전에 **실제 산출물을 확인**한다.

> 사용자 지시(2026-06-02): "기록물은 압축 전에 항상 최신 상태로 유지·점검 완료되어야 한다. 압축을 기다리지 말 것."

**압축의 사용자 신호**: 화면 우측 하단 진행 링이 **파랑→노랑**으로 바뀌고 차오르는 정도로 사용자가 압축 임박을 예측한다. 단, 어시스턴트는 이 UI 링을 직접 볼 수 없다 → **상시·선제적 최신화**로 대체하여, 사용자가 노랑 링을 보더라도 기록물이 이미 안전하도록 한다.

규칙:
1. **상시 최신화 (압축을 기다리지 않음)**: 의미 있는 작업 단위(기능 완성·디자인 패스·진단·결정·산출물)를 마칠 때마다 **즉시** 해당 기록물을 반영한다 — 세션지침 / 프로젝트 `.claude/CLAUDE.md` 역류 / TRAP(`docs/production_lessons.md`) / 메모리 / `~/.claude/registries/{P}.md`. 압축 시점까지 미루지 않는다.
2. **턴 종료 전 점검 (체크포인트)**: 의미 있는 산출물을 만든 턴은 응답을 마치기 전에 "기록물 5종(세션·프로젝트 CLAUDE.md·TRAP·메모리·registry) 중 갱신 필요한 것"을 빠르게 자가 점검 → 누락 발견 시 그 턴 안에서 보강한다.
3. **병렬 처리 (주 작업 중단 금지)**: 기록 점검·갱신은 주 작업을 멈추지 않고 병렬로 수행한다(사용자 피드백: 기록 위해 작업 흐름을 멈추지 말 것).
4. **결과**: 압축이 언제 발생하든 직전 맥락이 파일에 보존되어 무손실 복원 가능.

### 사용자 제공 자료 즉시 자원화 (User-Provided Asset Persistence)

> 사용자 지시(2026-06-02): "중요한 자료는 대화 압축 시 소실되지 않게 바로바로 폴더 내 자원으로 저장." 계기: 사용자가 채팅으로 첨부한 와가마마 로고 원본이 압축 후 소실되어 픽셀 단위 비교가 불가했음.

**사용자가 채팅으로 제공한 중요 입력 자료(이미지·로고·문서·참조 파일·샘플 데이터 등)는 받는 즉시 프로젝트 폴더에 파일로 저장한다.** 채팅 첨부물은 컨텍스트 압축 시 소실된다.
- **대상**: 브랜드/로고 원본, 레퍼런스 이미지·디자인 시안, 사양서·스펙 캡처, 샘플 데이터 등 추후 비교·재사용할 모든 근거 자료.
- **저장 위치**: 프로젝트 내 적절한 경로(`assets/`·`docs/`·`memory/` 또는 기능별 폴더). 파일명은 의미 있게(브랜드 원본 예: `assets/brand/{브랜드}_logo.{확장자}`).
- **시점**: 받는 즉시(주 작업 시작 전). 저장 후 경로를 사용자에게 한 줄 안내.
- **연계**: 저장 자원의 위치·용도는 reference 메모리 또는 프로젝트 `.claude/CLAUDE.md`에 기록(압축 후에도 위치 추적 가능). 위 "압축 전 선제적 기록물 점검"과 한 쌍.

### 지침 변경 자동 감지 + 행동규칙 기계 가드 (Instruction Hooks)

> 도입: 2026-06-11 (P38 세션, 사용자 지시: "왜 자동으로 전역지침 내용 후크 안됐는지 검토해서 보완"). 원인: 지침은 **세션 시작 시 1회 스냅숏 로드**라 세션 도중 타 세션의 갱신이 자동 반영되지 않고, 행동 규칙(Safari 등)에 기계 강제 장치가 없었음.

**전역 hooks(`~/.claude/settings.json`)가 자동 수행한다:**
- **UserPromptSubmit** `~/.claude/hooks/claude_md_watch.py`: 매 사용자 메시지 제출 시 전역지침 + cwd→$HOME walk-up 경로의 모든 `.claude/CLAUDE.md` 변경(타 세션 갱신 포함)을 mtime/sha로 감지 → "재Read하라" + 변경 섹션 요약을 컨텍스트에 주입. **알림 수신 시 해당 파일을 Read로 다시 읽고 새 규칙 적용 의무.** (상태: `~/.claude/.cache/md_watch/{세션ID}.json`, 30일 자동 정리)
- **PreToolUse(Bash)** `~/.claude/hooks/safari_guard.py`: `.html` 대상 `open` 명령에 `-a Safari`가 없으면 deny + 사유 반환 (HTML 산출물 Safari 규칙의 기계 이행).
- **SessionStart** `~/.claude/hooks/session_start.sh`: 레지스트리 SSOT·4계층 번호에 더해 **자주 위반되는 행동규칙**(Safari·P{N} 표기·누적 보고서 섹션 재확인·검수 페이지·압축 포크 +1)을 주입 — 압축 후 재시작 시에도 발화하므로 규칙 유실 방지.
- 새 "자주 위반 규칙"이 생기면: ① session_start.sh에 1줄 추가 ② 기계 차단 가능하면 PreToolUse 가드 스크립트 추가.

### 대화 전문 자동 MD 미러 (Transcript MD Mirror)

> 도입: 2026-06-11 (P41 세션, 사용자 지시: "압축으로 컨텍스트가 유실되지 않도록 주기적으로 모든 대화를 MD로 저장, 전 세션 전파")

**전역 hooks가 자동 수행한다 (Claude의 별도 저장 작업 불필요):** `~/.claude/settings.json`의 **Stop(매 턴 종료, async) · PreCompact(압축 직전) · SessionEnd** 훅이 `~/.claude/scripts/transcript_to_md.py`를 실행해 현재 세션 transcript JSONL을 읽기 좋은 MD로 변환 저장한다.

- **저장 위치 (2중 미러)**:
  1. `{프로젝트}/memory/sessions/transcripts/{세션UUID}.md` — cwd에 `.claude/` 또는 `memory/`가 있을 때 (iCloud 동기화로 타 맥 복구 가능)
  2. `~/.claude/transcripts_md/{프로젝트슬러그}/{세션UUID}.md` — 항상 (중앙 미러, cron 백업 대상)
- **내용**: 사용자·Claude 발화 전문 + 도구 호출 1줄 요약(🔧) + 도구 결과 300자 미리보기(↩️) + 압축 요약(📦). 서브에이전트 사이드체인 제외. 매 실행마다 전체 덮어쓰기(원본은 JSONL이 보존).
- **Claude 의무**:
  1. **압축 복원·세션 재개 시** 세션지침과 함께 이 미러 MD를 참조해 유실 맥락(특히 사용자 원문 발화)을 복원
  2. 훅 미작동 의심 시 수동 실행: `echo '{"transcript_path":"<JSONL경로>","cwd":"<프로젝트>"}' | python3 ~/.claude/scripts/transcript_to_md.py`
  3. 이 미러는 기록물 5종(세션지침·프로젝트 CLAUDE.md·TRAP·메모리·registry)을 **대체하지 않는다** — 원시 대화 보존층일 뿐, 구조화 기록은 기존 규칙대로 유지
- **전파**: user-level 설정이므로 모든 신규 세션에 자동 적용. 이미 실행 중인 다른 세션은 재시작 후 적용.

### 압축 감지 시 대응

자동 컨텍스트 압축이 발생하면:
1. 사용자에게 "⚠️ 압축 발생" 알림
2. 세션지침 즉시 갱신 + **포크번호 +1 자동 부여** (`P{N}.{C}.{F+1}.0`) — ⚠️ **채팅번호 건드리지 말 것** (타 채팅 충돌 방지 핵심)
3. **`## 금지/확정 사항` 섹션을 가장 먼저 확인** — 이전 세션 금지/불가 사항 필수 전달
4. **사용자에게 새 채팅을 열라고 안내하지 않는다** — 사용자는 같은 채팅에서 계속 작업
5. 유실 의심 맥락은 **대화 전문 미러** `memory/sessions/transcripts/{세션UUID}.md`에서 원문 복원
