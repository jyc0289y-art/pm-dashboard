> **시행**: 2026-07-10 (P2.17 제1차 전체회의에서 정립 — P28 IPT + P36 소생패널 + P37/38 분과 + P42 재심 형식을 종합·개선한 최신 완전판)
> **정본 예시**: P2 `GEANT4_claude/docs/panel/20260710_220216_*` 시리즈 (사전브리핑 → 7분과 → 전체회의 → 적대비평 → 속개 → 교육요약 풀 사이클)

## 1. 분과 설계 원칙

1. **상설 분과 4~6개**: 프로젝트 도메인별 (예: 물리·검증 / SW·아키텍처 / 제품·사용자가치 / 규제·품질보증 / 로드맵·자원배분)
2. **특별 분과 2개는 거의 항상 포함**:
   - **감사 분과 (AUDIT)** ★ — 과거 결과 독립 재검증. 타 분과 결론에 구속되지 않음. 실제 파일 Read + 해석적 재계산 의무. 판정 등급: 적정/주의/결함/재검증 필요
   - **사용자교육 분과 (EDU)** ★ — 회의 결과를 오너 지식 수준에 맞게 요약. 오너 프로파일(강점/초심 영역) 명시 필수
3. 분과당 패널 5인 내외 — **가상 인물**(실존 인물 금지), "이름(배경) — 전문 분야" 형식, 세계 최고 수준 전문성 시뮬레이션
4. 분과가 놓친 관점 보완은 PM 책무 (예: P2에서 규제·QA 분과는 오너가 요청하지 않았으나 PM이 신설)

## 2. 회의 파이프라인 (7단계)

```
① 사전브리핑 (사무국) — 프로젝트 현황+정량 성과+미결+위험+회의 규칙을 단일 문서로. 전 패널 공통 사실 기반
② 분과 패널토론 (병렬) — 발제(패널당 1건) → 교차토론(최소 8왕복, 구체적 기술 반론 필수, 덕담 금지)
   → 결의({분과ID}-R{n}, 합의/표결/보류 구분+근거 1줄+표결 수) → 미결(재론 트리거 명시) → 전체회의 상정 안건
③ 감사분과 독립 감사 — ②와 병렬이되 결론 비구속. 수치는 재계산으로 검증
④ 전체회의 (Plenary) — 감사 특별보고 우선 처리(피감 분과 소명→수용/재심/기각 표결, 피감 분과 기권제)
   → 분과별 보고 → 쟁점 교차토론(분과 간 이해충돌 명시 처리) → 의결(PL-{n}: 만장일치/다수결/PM 결정/보류 구분)
   → Action Item(담당 분과+기한+우선순위) → 오너 갈림길(U-{n}) 분류
⑤ 적대비평 (Devil's Advocate) — 전체회의 결론 공격: 침묵한 주제, 결의 간 모순, 실행 가능성, 감사 무마 흔적
⑥ 속개(續開)/재심 — 유실 분과 재소집분·감사 재심 판정(3값: RESOLVED/ACCEPT_NEW/REJECT)을 통합해 최종 의결 완성
⑦ 사용자 교육 요약 — 3단계 깊이(한줄/문단/상세) + 용어 미니사전(오너 전문 분야에 비유) + 질문 템플릿
```

## 3. 핵심 규칙 (P2에서 검증된 것)

- **오너 갈림길(U-{n})**: 오너만 결정할 항목은 보류로 분류하되, 각 항목에 쉬운 설명+선택지+회의 추천+추천 근거를 붙인다. 90일 오너 결정 슬롯 상한(예: 5개)을 정해 초과분은 이월
- **오너 도메인 주권 (검수 이관의 경계)** ★: 오너의 전문·철학 근간(교수철학·설계사상·도메인 판단 등)에 닿는 적대비평/분과 지적은 **'정합성 회복'처럼 보여도 패널·PM 전결 금지 → 반드시 U-{n}으로 오너 상신**. 특히 **EDU가 '오너 판단 필요'로 올린 항목을 PM이 자동 처리하면 위반**. '검수는 패널이, 오너 개입 최소화'의 경계는 **데이터·기계·구현 정합성**까지이며, **도메인 철학은 오너 고유 영역**. (P37 TRAP-010 도출: 패널이 오너 교수철학(전략적 L1 활용)을 '유의점↔대본 모순 해소'로 자동 번복 → 오너가 되돌림)
- **소수의견 보존**: 부결된 소수의견은 이름·논지·재론 게이트와 함께 기록 (삭제 금지)
- **잠정 딱지**: 미검증 전제 위의 결의는 "원장 대사 전 잠정" 딱지 + 피벗 조건 명시
- **공개 게이트**: 공개·제출용 수치는 통계 충분성+출처+한계 배지 의무 (프로젝트별 구체화)
- **감사 지적 시 재심 의무**: critical/major 채택 → 소관 분과 재심 자동 발효

## 4. 기록물 규칙

- 위치: `{프로젝트}/docs/panel/` (또는 `docs/meetings/`, `docs/committees/`)
- 파일명: `{YYYYMMDD_HHMMSS}_{NN}_{종류}_{주제}.md` — NN은 파이프라인 순서 (00 사전브리핑, 01~ 분과, 08 전체회의, 09 적대비평, 10 교육요약, 11+ 속개)
- `{ts}_meta.json`: 회의 시리즈 메타 (분과 목록, 파일 매핑, 의결 수, 오너 갈림길 수)
- HTML 보고서: 전역지침 검수 페이지 규칙 적용 (P{N} 배지, 체크리스트, 피드백 복사, Safari로 열기)
- 기존 회의록은 절대 덮어쓰지 않음 — 속개·정정은 새 파일

## 5. 실행 메커니즘 (Claude 오케스트레이션 레시피)

- **Workflow 도구** 5 Phase: Research(참조 형식+프로젝트 현황, 병렬) → Briefing → Panels(병렬) → Plenary+적대비평 → Education
- 각 분과 agent에게: charter(패널 구성+의제) + 사전브리핑 본문 + 공통 토론 규칙 + 프로젝트 파일 Read 권한 + Write로 회의록 직접 저장 + schema로 요약 반환 {file_path, summary, resolutions[], open_issues[], plenary_agenda[]}
- Plenary agent는 분과 요약 digest만 받음 (전체 회의록 아님 — 토큰 절약)
- **실패 프로토콜**: API 오류로 유실된 분과는 표준 Agent로 재소집(재소집 사유 회의록에 명시) → 전체회의는 "속개" 형식으로 통합 의결 (1차 의결 PL 번호 연속 유지)
- 감사 agent에게는 구체적 감사 대상 목록 + 기준값(감마상수 등) + "실제 파일 열어 재계산" 지시 필수 — 이것이 P2에서 간판 수치의 변환 오류 상쇄 가능성(AUD-H)을 잡아냈다
