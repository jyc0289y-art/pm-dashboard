## 작업 요약
P18.8.2.0에서 :8503 standalone MJPEG로 단일 영상은 작동하게 됐으나, 관제 대시보드의 카메라 그리드는 단일 버퍼라 모든 타일이 같은 영상을 보여주는 문제. Phase C에 해당하는 **멀티 카메라 본격 구현**을 사용자 위임으로 진행. stream_server 버퍼를 dict화하고, CameraWorker/WorkerPool 신규 구현, URL 파라미터화 + 사이드바 워커 관리 UI 통합.

(트럭 분류기 통합은 grep 결과 이미 Mode C에 통합되어 있어 skip)

## 주요 결과물

### stream_server.py — 멀티 버퍼화
- `_latest_jpeg`(단일) → `_latest_jpegs: dict[camera_id, bytes]`
- `update_frame(frame)` (legacy) + `update_frame(camera_id, frame)` (multi) 모두 지원
- URL 라우팅:
  - `/stream/{cam_id}` MJPEG 스트림
  - `/snapshot/{cam_id}` 단일 JPEG
  - `/viewer/{cam_id}` 카메라별 뷰어 HTML
  - `/cameras` 활성 카메라 JSON (디버깅)
- module-level `__getattr__`로 `_latest_jpeg` legacy 별칭 보존 (tornado_mjpeg silent fail 방지)
- `remove_camera()`, `list_active_cameras()` 공개 API

### engine/core/camera_worker.py — 신규
- **CameraWorker**: 카메라별 독립 스레드
  - cv2.VideoCapture → YOLO.track → reclassify_truck → vehicle_classifier → F1~F5 룰엔진 → FrameAnnotator → stream_server.update_frame(cam_id, ...)
  - 룰엔진(WrongWay/Pedestrian/Congestion/Accident/WeatherAdapter) 인스턴스는 카메라별 독립
  - **YOLO 모델/분류기는 외부 주입 → 모든 워커가 공유** (GPU 메모리 절약 핵심)
  - `on_event` 콜백으로 UI 알림 패널과 연동
  - 재연결 로직 (max_reconnect=5, sleep 2s)
- **WorkerPool**: 그리드 변화 감지 + 워커 라이프사이클 관리
  - `ensure(cameras)` → 신규 카메라 시작, 사라진 카메라 정지 + 버퍼 정리
  - `max_workers` cap (GPU 한계 대응, 기본 4)
  - `status()` 메서드로 사이드바 실시간 표시

### app/streamlit/camera_grid.py — URL 파라미터화
- 스냅샷: `/snapshot` → `/snapshot/{cam_id}` (각 타일 독립 영상)
- 풀스크린: `/stream` → `/stream/{cam_id}`
- **스냅샷 자동 갱신**: `<img onload="setTimeout(...500ms)">` 폴링 (~2fps, 그리드 미리보기)

### app/streamlit/app.py — 관제 대시보드 모드
- `load_config_for_workers()` 헬퍼 신규 (config 싱글턴)
- `WorkerPool` 싱글턴 `st.session_state.worker_pool`
- 사이드바 컨트롤:
  - 동시 감지 카메라 수 (1~6)
  - 워커 해상도 (640/960/1280)
- 그리드 레이아웃에 따라 대상 카메라 자동 결정 (Watch List > Favorites > 나머지 순)
- `pool.ensure()` 매 rerun에서 호출 → 그리드 변화 자동 반영
- 사이드바에 워커별 FPS/상태 실시간 표시
- `on_event` 콜백으로 이벤트 자동 add_event 연동

## 핵심 결정사항
1. **모델 공유, 룰엔진 분리** — YOLO/EfficientNet은 모든 워커가 같은 인스턴스 사용 (GPU 메모리), 룰엔진은 카메라별 독립 인스턴스 (각 카메라의 캘리브레이션/사고 추적이 독립적이어야 하므로)
2. **WorkerPool ensure()는 매 rerun 호출** — Streamlit 재실행 모델과 자연 호환. 중복 시작은 dict key 체크로 방지
3. **max_workers 사이드바 슬라이더** — Mac MPS yolo11l 1280px 기준 동시 2~3개 권장. GPU 환경에 따라 사용자 조정 가능
4. **legacy 호환 우선** — update_frame 두 시그니처 모두 지원, _latest_jpeg `__getattr__` 노출로 기존 코드 무중단
5. **스냅샷 폴링은 onload→setTimeout** — Streamlit의 매 rerun과 분리된 클라이언트 측 폴링 (~2fps). 그리드는 미리보기 정도로 충분
6. **트럭 분류기는 이미 통합** — Mode C app.py:603-604에 `classifier.reclassify_detections()` 이미 호출 중. 사용자가 본 오검출은 분류기 정확도 한계 (별도 작업 필요)

## 금지/확정 사항
- ❌ WorkerPool 인스턴스를 매 rerun마다 새로 만들지 말 것 — 워커 thrash 발생
- ❌ tornado_mjpeg.py 의존하는 신규 코드 작성 금지 (Streamlit 1.56+ silent fail)
- ❌ stream_server `_latest_jpeg` 직접 참조 신규 금지 — `_latest_jpegs.get(cam_id)` 또는 헬퍼 사용
- ✅ 멀티 카메라 URL은 `/stream/{cam_id}`, `/snapshot/{cam_id}` 일관 사용
- ✅ CameraWorker는 daemon=True 스레드, stop() 호출 시 timeout=2.0s 내 종료
- ✅ `python run_highlink.py`로 기동 (streamlit run 직접 사용 금지, P18.8.2.0)

## 사용자 검증 요청 사항

### 즉시 확인
- 관제 대시보드 모드 진입 → 사이드바 "동시 감지 카메라 수" 1~3 조절 → 그리드 레이아웃 2x2/2x3 전환 → 각 타일에 독립 영상이 표시되는지
- 사이드바 "활성 워커" 섹션에 카메라별 FPS 표시 확인
- 풀스크린 모드(타일 클릭) → 단일 카메라 풀 MJPEG 스트림 확인

### GPU 한계 측정 (사용자 직접)
- 동시 1, 2, 3, 4 워커 시도 → 각 워커 FPS 기록
- Mac MPS는 yolo11l 1280px에서 동시 2개가 한계로 예상 (단일 30fps → 2개 ~12fps 추정)
- imgsz를 960으로 낮추면 동시 3~4개 가능할 수도
